# Arm C improvement loop — executable methods with measured limitations

1. **Read only authorized new information.** Re-evaluate live assumptions and unbound open questions first, then scoped code-linked questions, plus up to five existing highest-priority open questions. Independently examine each question; a cross-walk is not bundling.
2. **Select methods by evidence need.** Consider the repertoire, then actually apply only appropriate skills. Explain why a considered method was inapplicable; do not create skill-use records to make a count.
3. **Capture a behavior baseline.** Run actual entrypoint and self-authored tests. Save exact raw streams, exit code, source/test identity and clock/timeout constraints, separately from interpretation. `local_gate.py` does this and reports a timed-out run as incomplete.
4. **Sense evolving structure.** Use `maintenance_sensor.project_snapshot` with explicit *project roots*, complete parse coverage, and stable tool version. Inspect absolute high-mass, ratio, changed responsibilities, added/removed files, and persistent hotspots. Lower scores are not an architectural verdict.
5. **Challenge the sensor itself.** If a reported improvement is caused by a changing denominator, unscanned source, source rename, unsupported language, scope mismatch or metric definition, write a positive case and negative control first. Repair the smallest useful capability and bump the version when its meaning changes. Do not retroactively assign the capability to earlier checkpoint agents.
6. **Contemplate structural options.** Compare keeping a coherent unit, narrow helper, representation change and responsibility boundary. Refactor only if the new boundary localizes a genuine reason to change, and test the behavior before and after. Preserve failures and recover using only own authorized evidence.
7. **Evolve skills.** Record the trigger, method attempted, falsifier, true observed outcome, remaining applicability limits and retirement trigger. New specialized skills must justify future value and review cost. Git is history; no permanent retirement archive.
8. **Retest and decide.** Run cumulative source tests and separate tool tests. Accept the improvement only at its measured scope. Classify external/Docker checks as NOT_RUN, not PASS. Preserve unknowns without speculating that every unknown has been discovered.

## Unproven proposition
